# 桌宠玩《杀戮尖塔2》

本功能使用 [Gennadiyev/STS2MCP](https://github.com/Gennadiyev/STS2MCP) 的游戏模组。
桌宠直接连接模组的本机 HTTP 接口，与该项目的 Python MCP 服务使用相同的游戏操作接口，因此不需要另开 Python MCP 服务。

## 安装模组

1. 关闭《杀戮尖塔2》。在 Steam 库中右键游戏，选择「管理 → 浏览本地文件」，找到安装目录。
2. 打开 [STS2MCP 发布页](https://github.com/Gennadiyev/STS2MCP/releases/latest)，下载与你当前游戏版本兼容的模组。兼容版本以发布说明为准，测试前建议备份存档。
3. 按上游安装说明，将 `STS2_MCP.dll` 和 `STS2_MCP.json` 放入游戏安装目录中的 `mods` 文件夹；不要覆盖游戏本体文件。
4. 启动游戏，在游戏设置中启用模组，接受首次启用模组时的提示。
5. 手动新开或继续一局单人游戏，停在地图或战斗等可操作界面。

模组默认监听本机端口 `15526`。桌宠只访问 `127.0.0.1`，不通过系统代理，也不会开放远程控制。
该模组允许程序真实操作对局，不是只读插件；先用不重要的对局测试。

## 使用桌宠

1. 启动桌宠，确认「聊天设置…」中的接口可用，模型支持工具调用。
2. 在角色上右键，打开「杀戮尖塔2（STS2MCP）」子菜单，勾选「开启接入」。这一步只检查连接，游戏保持暂停。
3. 先试「只行动一步」；确认正常后再选择「开始 / 继续自动游玩」。
4. 随时选择「暂停自动游玩」，或点击聊天栏的停止按钮。模型还在思考时暂停，后续返回的决定不会再执行。已发出的游戏操作不能撤回。

文字和语音使用相同指令：

| 指令 | 作用 |
| --- | --- |
| 去玩尖塔 / 继续尖塔 | 开始一段自动游玩 |
| 暂停尖塔 / 停止尖塔 | 停止后续游戏操作 |
| 尖塔走一步 | 只推进一个动作 |
| 尖塔：优先防御 | 本次行动采用这条指令，之后仍按设置中的长期目标行动 |

「尖塔设置…」包含端口、长期目标、行动间隔、每段操作上限、决策超时和旁白开关。
默认操作上限是 60 次，不代表 60 个战斗回合；出一张牌、选一个奖励都算一次。到达上限后手动继续可开始下一段。
对局状态会提供给聊天模型，行动结果会进入桌宠的本地短期记忆；旁白使用现有朗读配置。
开启游戏旁白时，每个战斗回合只点评一次整回合的攻守和资源取舍，采用简短主播口吻，最长四十字；
同回合后续出牌不再生成旁白。动作和点评合并生成，避免为旁白单独请求模型。
等朗读结束后再核对游戏状态并行动；
仅文字模式则等文字显示后行动。聊天正在进行时会等待，不跳过旁白，也不会一边说上一步一边行动下一步。
说话期间暂停或打断，尚未执行的动作不会再发出；说完后状态改变时会重新观察。
关闭游戏旁白时仍按原先的无旁白模式行动。

旁白只说卡牌、敌人、地点等显示名称和简短中文理由，不朗读目标 ID、索引、工具名、参数、
策略评分标签或模组的原始返回内容。技术错误详情留在本地日志中，不混进游戏旁白。

## 策略 Skill 与继续行动

可以把 [mxnklimt/AI_slaythespire](https://github.com/mxnklimt/AI_slaythespire) 下载到项目的
`skills/ai-slay-the-spire-2/`。这是可选增强，未安装也能使用爬塔功能。
本仓库不重新分发该项目的策略文本，内容及使用授权以原作者仓库为准。

在本项目目录运行以下命令。目标目录已存在时不要重复克隆，也不要覆盖自己修改的策略：

```powershell
git clone https://github.com/mxnklimt/AI_slaythespire.git skills/ai-slay-the-spire-2
git -C skills/ai-slay-the-spire-2 checkout 904b6f59b98a6cfd77b4ae26f72f2746e4a97025
```

上面的提交是本次集成核对的参考版本，安装后重启桌宠即可加载。
桌宠按当前画面读取策略；战斗只加载战斗、药水和短板参考，选牌/升级/购物加载选牌评分，
非战斗时铁甲战士才加载战士卡牌标签。未验证的 `proposals/` 不作为正式规则，数值和目标以当前游戏状态为准。

选牌奖励可以主动跳过。模组可能保留被跳过的领奖入口，桌宠会记住本奖励页已跳过的那一份，
不再重新打开；其他奖励照常处理，只有剩余奖励都已跳过且前进按钮可用时才直接前进。
同场多份选牌奖励分别处理，暂停再继续不会丢失记录；离开当前奖励场景后清除记录。

不再因“没有唯一解”交还控制：

1. 返回多个合法工具调用时，只执行返回顺序中的第一个；其余丢弃，下一步重新观察。
2. 没有合法动作或只有分析文字时，读取新状态并让模型明确一次动作，共用本轮超时预算。
3. 仍没有动作时，使用当前状态中的保底动作：可打的牌和真实敌人目标、无法出牌时结束回合、跳过可跳过的卡牌奖励、选择当前可用路线/选项等。
4. 没有明确可用动作时等待下一次观察。断连、游戏错误、停止指令、操作上限和菜单/未知弹窗保护仍有效。

保底行为用来推进对局，不保证最优策略。不会猜测索引、伪造目标、批量执行过期动作，
也不会在 HTTP 失败后自动重放动作。日志 `sts2.action_selected` 的 `mode` 区分
`model`、`first_valid`、`repair`、`fallback`、`reward_cleanup`。

## 范围与限制

- 只支持单人对局。联机接口冲突会暂停，不绕过模组的同步限制。
- 支持出牌、结束回合、使用或丢弃药水、战斗选牌、奖励、地图、营地、商店、事件、卡牌/遗物/组合选择、宝箱和水晶球小游戏。
- 模型只能使用当前画面的工具，每次只执行一个动作。执行前状态改变时会重新观察，不执行基于旧状态的动作。
- 不提供菜单、存档删除、存档切换或放弃对局工具。主菜单、结束界面和未知弹窗需要你手动处理后继续。
- 不保证通关率，也不会修改游戏规则或使用一代游戏的固定数值代替当前状态。长局会消耗聊天模型额度，建议先用低操作上限验证。
- 关闭接入、暂停、重启桌宠都不会自动恢复游玩。

## 排查

| 表现 | 检查 |
| --- | --- |
| 连不上 STS2MCP | 游戏是否启动、模组是否启用、端口是否为 `15526`；点击「检查连接」 |
| 提示联机对局 | 先退出联机，进入单人对局 |
| 进入战斗就 HTTP 500 / 版本不兼容 | 游戏 v0.107 移除了 `CombatManager.IsPlayPhase`。旧版发布包可能仍调用此接口，需要使用包含上游 `IsPlayPhase` 兼容修复、针对当前游戏构建的模组，然后重启游戏；单纯重试或增加间隔无效 |
| 提示未提供出牌阶段 | 更新 STS2MCP，当前适配需要 `battle.is_play_phase` 字段 |
| 模型没有给出唯一动作 | 自动取一个合法候选，或明确一次后采用保底动作；可在日志查看 `sts2.action_selected` |
| 聊天连接中断 | 自动在原决策超时内短暂重试一次；持续失败时检查网络和代理，恢复后手动继续，不会自动重试游戏动作 |
| 跳过卡牌后仍能看到卡牌领奖入口 | 模组可能保留入口；桌宠会排除本页已跳过的奖励，处理其他奖励后前进 |
| 上一步无变化而暂停 | 手动观察游戏是否有动画、选牌或弹窗未完成，不要盲目重复点击 |
| 达到操作上限后暂停 | 这是正常的额度保护，选择「开始 / 继续自动游玩」继续下一段 |

`pet_runtime.log` 中的 `sts2.decision`、`sts2.action` 和 `sts2.error` 记录决策耗时、工具名、HTTP 方法、状态码与模组异常详情，不记录 API Key 或完整游戏状态。HTTP 失败后不会自动重复游戏动作。
`sts2.narration.start` / `sts2.narration.end` 记录前置旁白；`sts2.action` 只在旁白完成且动作被接受之后出现。

### 模组版本兼容

2026-10-10 测试时发现：旧 STS2MCP v0.4.0 发布 DLL 读取战斗状态时可能抛出
`System.MissingMethodException: CombatManager.get_IsPlayPhase()`，非战斗界面正常。
兼容构建使用 [上游提交 55e0648](https://github.com/Gennadiyev/STS2MCP/tree/55e064850a68f3b4cde7e5fd525bf9b2dec4e885)，
针对游戏 v0.107.1 的程序集编译；游戏升级后需要重新验证兼容性。
上游改用 `PlayerCombatState.Phase` 判断玩家出牌阶段，包含战斗读取与动作检查的兼容修复。

- 本仓库不包含游戏 DLL、模组编译产物或本地备份。优先安装上游与当前游戏匹配的发布包。
- 必须替换模组时，先备份原模组并正常退出游戏；替换后启动游戏、手动继续单人对局，再点桌宠「检查连接」。
- 清单仍标记上游版本 `0.4.0`，不能仅靠版本号判断是否包含此修复。
- 游戏再次更新后若接口继续变化，需要重新验证兼容性，不能保证此 DLL 永久适用。

开发验证：`python -m unittest discover -s tests -v`。测试使用本机模拟游戏服务，不会操作真实存档；真实对局效果需要安装模组后验证。
